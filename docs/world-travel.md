# 世界地图资源与运行合同

本文记录世界地图的资源格式、编号和呈现依据。资源能够导入不代表全部游历规则或画面都已验收；核心地图/会话切换与 Godot 呈现分别实现、验证。

## 共享资源

`LegacyAssetImporter` 将 `MMAP.IDX` / `MMAP.GRP` 的全部图像导入已有共享图集，bank 名为 `world`。它与 `scene/nnn`、`portrait` 共用相同的解码图像哈希、全局资产表和 `assets/sprites/atlas-*`，不会生成世界地图专用临时包、场景碎片或运行时导出缓存。

| Bank | 本地编号 | 索引规则 | 空记录 |
|---|---|---|---|
| `scene/nnn` | SDX 帧索引 × 2 | sentinel，末帧延伸至 EOF | 保留原指针向后别名 |
| `portrait` | HDGRP 帧索引 | 普通累计结束偏移 | 保持空图，不向后别名 |
| `world` | MMAP 帧索引 × 2 | 普通累计结束偏移 | 保持空图，不向后别名 |

MMAP 的普通 IDX 可以包含正偏移之后的零尾填充，零尾不增加新帧。地图中的图片 ID 保持原数值，读取精灵时通过 `world` bank 查找；不要在导入地图格子时预先除以二。人物、船以及地图图片都来自同一 MMAP bank。

为兼容独立的场景格式夹具，同时缺少 MMAP 两个文件时允许没有 `world` bank；仅缺一个文件时明确失败，且在读取图像、写图集之前检查。实际原版完整库应包含该 pair。旧格式 3 库虽然可能已经在 source vault 保存 MMAP 原始文件，仍可能缺少转换后的 `world` bank；应重新导入完整库，不在启动时临时拆包或导出另一套图集。

跨 bank 去重包括尺寸、锚点、索引和透明覆盖；相同像素但不同锚点不合并。RLE 的 skip 表示透明，run 中的索引 0 仍是有覆盖的像素；不能把调色板色号 0 一律设为透明。

## 地图格与建筑归属

五个原始层文件均为 480×480 有符号小端 16 位数据，每个文件 460800 字节，线性索引为 `y * 480 + x`：

| 文件 | 内容 |
|---|---|
| `EARTH.002` | 地面图片编号 |
| `SURFACE.002` | 地表装饰图片编号，0 时不绘制 |
| `BUILDING.002` | 建筑拥有者格的图片编号 |
| `BUILDX.002` | 覆盖格对应的建筑拥有者世界 X 坐标 |
| `BUILDY.002` | 覆盖格对应的建筑拥有者世界 Y 坐标 |

建筑可以覆盖多个格子。覆盖格的 owner 坐标必须作为一对解释，按 owner 去重后读取 `BUILDING(ownerX, ownerY)`，在 owner 的投影锚点绘制。BUILDX/BUILDY 不是贴图编号，也不是高度，不能套用小场景的建筑高度层。边界格或零坐标的解释由地图规则处理，不用简单的“单个坐标为 0 即无建筑”替代双坐标判断。

OpenLegend 先按 x-major 顺序绘制全部地面，再按 x-major 绘制非零 surface，最后把建筑、主角和船放进深度列表。`world_depth_order.cpp` 根据覆盖格及 owner 重排遮挡顺序；只用图片锚点的屏幕 Y 排序是近似呈现，不能据此声称复制原版遮挡。主角与船使用的 5000/6000 是深度列表内部标记，不应直接当作最终人物/船图片。

## 投影与角色图片

世界和小场景使用同样的 18×9 等角投影：`screenX = originX + (x-y)*18`，`screenY = originY + (x+y)*9`。绘制图片时再减去图像的 `offsetX/offsetY`。原 320×200 视图的缓存相对原点和宽屏跟随原点不同；新的窗口布局可以使用自己的相机原点，不应把原版固定屏幕坐标误作地图格坐标或额外高度。

方向顺序与核心一致：上 `(0,-1)`、右 `(1,0)`、左 `(-1,0)`、下 `(0,1)`。

| 对象 | 四方向基础图片 ID | 步进偏移 |
|---|---|---|
| 主角步行 | 5002、5016、5030、5044 | 站立 0；行走 2、4、6、8、10、12 |
| 船 | 7430、7438、7446、7454 | 0、2、4、6 |

OpenLegend 在船状态为 0 时显示主角，状态为 1 时显示相应船图片；船未被乘坐时还作为地图上的独立对象参加深度排序。主角随机待机存在额外帧，不应把基础步行帧表当作完整动画实现。当前资源导入保留整个 MMAP，未按上述帧表裁剪。

## 旅行与会话

五层地图归档为中央库 `data/main-map.bin`，初始世界坐标、朝向和两格船位置保留在 `gameplay.json` 的 `travel_start`。运行不再访问原版安装目录。旧库缺少这些字段时仍可预览场景，但出口会明确提示重新导入，不临时创建另一份资源包。

`WorldTravelRules` 判断步行地形、建筑覆盖、上下船、船头前探和场景双入口；入口条件读取会话中的元数据，条件 2 要求队内至少一人轻功达到 70。小场景三组出口返回世界，关联跳转按源场景入口类型选择目标的正常入口或跳转返回坐标。

抵达后先运行自动事件，再判断出口；事件把人移开时取消离场。`GameSession.Advance` 推进同一执行器与旅行淡幕，淡出后发布令牌，宿主先准备目标资源，再提交切换，失败恢复原视图。背包、队伍、变量、地图/事件修改和 RNG 由同一会话保留。界面“预览此场景”和“重新开始”显式另建会话。

主角家往返冒烟：`./run.ps1 -Smoke -TravelSmoke -Headless -Report .local/verification/travel.json`。去掉 `-Headless` 并加 `-Capture` 可保存世界途中与回家画面。本轮实际窗口验收主角家周边往返；乘船等规则由独立夹具覆盖。世界行走每 50 步的恢复、天气/调色板、随机待机尚未实现，不把这些规则测试称作完整世界游历验收。

## 来源与验证范围

只读参考：

- `OpenLegend-main/src/world/world_map.cpp`：MMAP 档案选择、五层读取、人物/船帧、绘制分层与深度输入。
- `OpenLegend-main/src/resource/packed_archive.cpp`：普通累计索引、零尾填充、SDX sentinel 与指针别名的区别。
- `OpenLegend-main/include/openlegend/render/rle_sprite_renderer.hpp`：图片 ID 除以二的原版索引规则。
- `OpenLegend-main/src/render/rle_sprite_renderer.cpp`：锚点相减、skip 与覆盖像素写入。
- `OpenLegend-main/include/openlegend/render/world_projection.hpp`：世界投影及旧缓存视图坐标。
- `OpenLegend-main/src/render/world_depth_order.cpp`：建筑 owner 去重、人物/船注入和遮挡顺序。

`WorldAssetTests` 使用独立编写的小档案，验证 world 双倍编号、普通 IDX 空帧、零尾、跨 bank 去重、可选 pair 与缺文件失败。合成夹具测试只证明格式合同；不替代真实资源导入、世界游历流程测试或 DOS 动态画面对比。
