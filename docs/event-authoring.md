# 事件与任务编写

## 内容与执行

原版 KDEF 在导入时转换为标准命令，MOD 直接编写相同命令。运行时只有纯 C# `EventRunner`，不解析 Lua、原版字节码或 C# 动态插件。Godot 只负责输入、对话、选择、动画显示和音效。

中央库的 `data/gameplay.json` 集中保存全局程序、对白、物品和人物定义，地图事件位于统一世界文件。自行编写的单个剧情叠加使用格式 1 的 `StoryDocument` JSON，命令枚举以 snake_case 保存，运行时通过 `-StoryOverlay` 显式应用；不需要复制基础库，也不向每个场景导出 `story.json`。旧格式 1/2 场景包仅兼容读取。

`party` 和 `world` 是导入后的不可变初始定义，`GameSession` 为每次运行建立独立的 `PartyState`、`SceneWorldState`，事件只修改运行时副本。它们不是存档：重新开始会恢复初始定义，完整存读档尚未接入。

## 一个选择

```json
{
  "id": 100,
  "commands": [
    {
      "id": 0, "operation": "choice", "arguments": [20],
      "text": "要接下任务吗？",
      "choices": [
        { "text": "接下任务", "target": 10 },
        { "text": "稍后再说", "target": 20 }
      ]
    },
    { "id": 10, "operation": "set_variable", "arguments": [0, 1] },
    { "id": 11, "operation": "end", "arguments": [] },
    { "id": 20, "operation": "end", "arguments": [] }
  ]
}
```

选择文本直接放在命令中；普通对话在 `dialogues` 中定义分页，再通过 `dialogue` 引用。以上程序还需在同一 story 中注册 `"variable_names": { "0": "my_mod:quest/progress" }`。变量初始为 0，保存在当前 `GameSession`，重新开始时清空；完整游戏存档尚未接入。

命令数组按执行顺序排列，普通命令执行后进入数组下一项。跳转使用**命令 ID**，不是数组下标，也不是原版相对偏移。最后一条命令必须是 `end`、`return` 或 `stop`。所有目标都必须是本程序内存在的命令。

## 标准命令

以下参数都是 `arguments` 中的整数。`T/F` 是条件成立/不成立的目标命令 ID。

| 命令 | 参数 | 行为 |
|---|---|---|
| `refresh` | 无 | 等下一次宿主推进后继续 |
| `dialogue` | 对话 ID、头像 ID、样式 | 显示分页并等待确认 |
| `random_dialogue` | 起始对话 ID、数量、头像、样式 | 用统一 RNG 选对白 |
| `add_item` | 物品 ID、数量 | 改背包并显示获得/消耗提示 |
| `adjust_item` | 物品 ID、数量 | 改背包，不显示提示；负数扣除 |
| `change_event` | 场景、事件、11 个字段 | 改触发器、图片、阻挡、坐标 |
| `animate` | 事件 ID、起始图片、结束图片 | 事件 -1 为主角；图片步进 2 |
| `face` | 朝向 0–3 | 东北、东南、西北、西南 |
| `sound` | 音效 ID | 派发中央库中登记的事件 WAV 音效 |
| `jump` | 目标 | 无条件跳转 |
| `branch_item` | 物品 ID、最少数量、T、F | 检查当前背包 |
| `branch_item_exists` | 物品 ID、T、F | 检查原版物品槽 ID 是否存在，不要求正数量 |
| `branch_used_item` | 物品 ID、T、F | 检查本次触发使用的物品 |
| `branch_all_items` | 五个物品 ID、T、F | 五个原版物品槽 ID 均存在，不要求正数量 |
| `branch_variable` | 变量 ID、比较方式、值、T、F | 检查任务变量 |
| `branch_event` | 场景、事件、字段、期望值、T、F | 检查当前事件字段是否相等 |
| `choice` | 取消目标 | 还需 `text`、2–6 个 `choices`；-1 禁止取消 |
| `call` | 程序 ID | 执行子程序后返回下一项 |
| `return` | 无 | 返回调用者；根程序中则结束 |
| `end` | 无 | 结束当前程序；子程序中返回调用者 |
| `stop` | 无 | 结束整次事件，不恢复调用者 |
| `wait` | 毫秒 | 等待 0–3600000ms，期间锁定玩家移动 |
| `set_variable` | 变量 ID、值 | 写任务变量 |
| `add_variable` | 变量 ID、增量 | 加减任务变量，检查整数溢出 |
| `set_tile` | 场景、层、X、Y、值 | 改指定场景运行时地图；场景 -2 为当前图 |
| `teleport` | X、Y | 改主角坐标，不累计行走步数 |
| `fade` | 黑场目标、毫秒 | 目标 1 淡至黑场，0 从黑场恢复；0–60000ms，期间阻塞剧情 |
| `pan_camera` | 起点 X、Y、终点 X、Y | 仅移动镜头，X 后 Y，包含起点、不包含终点 |
| `scripted_walk` | 计数起点 X、Y、计数终点 X、Y | 从实际玩家位置逐步尝试移动，X 后 Y，不传送到计数起点 |
| `animate_pair` | 第一事件、第一图片起点、第一终点、第二事件、第二图片起点 | 第一范围决定帧数，先写第一目标再写第二目标，双方图片每帧加 2 |

角色与队伍命令使用 `party` 中的角色 ID。属性用原版 182 字节人物记录的**字索引**，不是字节偏移。`branch_role` 的最小、最大值都包含端点。

| 命令 | 参数 | 行为 |
|---|---|---|
| `join_party` | 角色 ID | 加入六人队伍，转移携带物品；正数量物品显示获得提示 |
| `leave_party` | 角色 ID | 离队并紧凑排列成员，清理装备与修炼占用；主角不离队 |
| `dismiss_party` | 无 | 全体同伴离队，并隐藏原版指定的 36 个地图事件 |
| `branch_party` | 角色 ID、T、F | 检查角色是否在队伍中 |
| `branch_party_full` | T、F | 检查六个成员槽是否已满 |
| `branch_party_female` | T、F | 检查队伍是否有性别值为 1 的成员 |
| `rest_party` | 无 | 对伤势小于 33 且未中毒的队员恢复生命、内力、体力并清除伤势 |
| `clear_party_mp` | 无 | 将队员当前内力归零 |
| `set_role_attribute` | 角色 ID、属性字索引、值 | 直接设置可写属性，不允许覆盖身份和姓名字节 |
| `add_role_attribute` | 角色 ID、属性字索引、增量 | 修改属性，并按相应规则限幅；需要时显示增长提示 |
| `branch_role` | 角色 ID、属性字索引、最小值、最大值、T、F | 检查属性是否落在闭区间 |
| `learn_magic` | 角色 ID、武功 ID、提示标志 | 写入首个空武功槽，满时覆盖第 0 槽；标志 0 显示提示 |
| `set_magic` | 角色 ID、槽位、武功 ID、熟练值 | 指定武功槽；槽位 -1 按首空槽规则选择 |
| `role_add_item` | 角色 ID、物品 ID、数量增量 | 修改人物的四个携带物品槽，优先匹配已有 ID，其次空槽 |
| `notice_role` | 角色 ID、属性字索引 | 显示当前属性并等待确认 |
| `add_fame` | 增量 | 修改主角声望，并检查原版十四天书与家中武林帖事件条件 |

常用人物字索引：14 性别、17 当前生命、18 生命上限、19 伤势、20 中毒、21 体力、40 内力性质、41 当前内力、42 内力上限、43 攻击、44 轻功、47 用毒、56 品德、59 声望、60 资质。武功 ID 在 63–72，熟练值在 73–82；携物 ID 在 83–86，数量在 87–90。完整定义以 `RoleWords` 为准。武功槽位为 0–9，武功 ID 0 表示空槽。

世界地图数据命令不需要把目标场景显示出来；`change_event`、`set_tile`、`branch_event` 同样可以引用 `world` 中的其他场景。

| 命令 | 参数 | 行为 |
|---|---|---|
| `increment_event_scripts` | 场景、事件、交互增量、物品增量、自动增量 | 为三个事件脚本编号分别加增量；事件 -2 为触发事件 |
| `replace_tiles` | 场景、层、旧值、新值 | 替换指定场景整层中所有匹配值 |
| `open_scene` | 场景 ID | 将有元数据的场景入口条件设为 0 |
| `open_all_scenes` | 无 | 开放入口，再保留原版例外：2/38 条件为 2，75/80 为 1 |
| `branch_books` | T、F | 当前场景事件 11–24 的显示图片都等于 4664 时成立 |
| `move_shop` | 无 | 通过事件执行器既有 RNG，在五家客栈迁移韦小宝商店事件 |

变量比较方式：0 等于、1 不等于、2 小于、3 小于等于、4 大于、5 大于等于。变量使用带命名空间的名字，避免不同任务共享含义不明的标志位。变量 ID 属于合并后的公共定义，叠加内容不能与基础变量使用重复 ID。

地图层：0 地面、1 建筑、2 装饰、3 事件索引、4 建筑高度、5 装饰高度。图像编号沿用原版双倍编号，动画首尾必须是偶数。

`animate` 继续要求非负偶数图片和正常范围。`animate_pair` 单独保留原版 44 的有符号字与低 16 位写入规则，允许第一起点大于终点时零帧、奇偶不同时不补齐终点；目标 -1 为玩家，目标相同时第二次写入覆盖第一次。原版第六个“第二终点”参数未读，标准命令不接收它。

`pan_camera` 的单轴视口原点是 `clamp(int16(coordinate-11),0,36)`，另一轴保持；演出结束不立即重置镜头，后续成功移动、传送或切图时恢复常规跟随。`scripted_walk` 检查建筑、高度、事件与地形阻挡，阻挡仍推进方向和步行图片、消费一个计数；它不增加手动步数，也不逐格触发自动剧情。完成时归零步行图片偏移并刷新站立状态。镜头与双动画每帧等待两个名义 BIOS tick，剧情行走每步等待三个；这些仍由同一个事件执行器推进。三种命令最多 4096 步或帧，超限在命令校验时拒绝。

`change_event` 的 11 个字段依次为：阻挡、原 index、交互脚本、物品脚本、自动脚本、起始图片、终止图片、显示图片、图片延迟、X、Y。字段 -2 保留；脚本 -1 关闭。场景 -2 表示当前场景，事件 -2 表示本次触发事件。事件 -1 还会移除触发格的事件映射，普通 NPC 修改优先使用明确事件 ID。

`increment_event_scripts` 使用有符号 16 位回绕，计算结果 -2 是真实脚本编号，不是保留哨兵。人物属性、人物携物数量、主背包和任务变量的加减采用检查溢出的 32 位运算；它们不模拟 DOS 任意内存覆盖。`add_role_attribute` 对资质、轻功和品德限制为 0–100，攻击不低于 0；增加生命/内力上限时同步更新当前值。`set_role_attribute` 是直接写值，不能假定它具有同样限幅。

重复邀请已在队伍中的角色、队伍已满时邀请，均不改变队伍或角色物品，这是重制明确采用的规范化行为。人物携物槽可以保留数量为 0 或负数的物品 ID；加入队伍时，仅正数量进入主背包，0/负数量只保留物品 ID 存在标志，不减少主背包。`initial_inventory` 只保存正数量，`initial_item_ids` 独立保留原始槽位的物品 ID；缺省时从初始背包的键推导。原版 18/43 的 ID 检查转换为 `branch_item_exists`，数量判断使用 `branch_item`。

## 三种触发方式

- 面向物件交互：执行事件字段 2 的程序，使用物品 ID 为 -1。
- 行囊选中物品并点击使用：验证确实持有物品，执行面前事件字段 3 的程序，传入物品 ID。
- 移动到事件格并完成呈现：执行事件字段 4 的自动程序。

使用物品不会自动消耗它，脚本需要显式 `adjust_item`。一次性事件需要修改自己的脚本或任务变量。事件运行时拒绝重入和手动移动，选择、等待和动画期间也一样。子程序继承触发事件、位置和使用物品上下文。

## 校验与诊断

加载时检查命令参数、跳转边界、对话、物品、变量、调用引用及更换后的脚本引用；更换到暂不支持的原版脚本允许登记，但触发时会明确拒绝。递归调用不支持，嵌套上限 32 层。

启动事件前，检查本程序及所有被调用程序对角色和世界数据的要求。例如引用包中不存在的场景，会在发放前面的奖励之前拒绝启动。旧包可以保持 `party` / `world` 为 null；角色命令要求导入的角色数据，远景命令要求目标场景存在，入口修改和全局退队命令要求导入的世界数据，缺少能力时不会伪造成功。旧包的当前场景事件、地图和天书判断仍可运行。运行中仍可能因库存不足或整数溢出失败；已经提交的合法动作不会自动回滚。

每次连续执行最多 10000 条命令，整次事件最多 100000 条，避免错误循环卡住游戏。保留最近 64 条执行记录，包含程序 ID、命令 ID 和命令类型。错误提示包含具体程序和命令位置。确认与选择均检查单调令牌，旧响应和重复点击不能推进新内容。

## 原版导入范围

当前 52 种标准命令可转换原版 0–67 中的 59 个编号，另支持结束标记 `-1`。尚未转换的 9 个编号为：`6, 8, 15, 24, 57, 58, 62, 64, 66`，涉及战斗、离场音乐、死亡/读档、特殊开门、武林大会、结局、商店和音乐播放。25/30/44 已转换为镜头平移、剧情行走与双动画；13/14 转换为 `fade`，时长暂取 450ms，是重制近似值，不是原版逐帧测量结果。

原版条件目标按 `本条字偏移 + 指令宽度 + 分支偏移` 计算，再转成标准命令 ID。导入器从入口遍历两条分支，允许分支越过另一条分支的终止指令，拒绝跳入参数区或越界；不可到达的填充不作为剧情执行。

55 号按原版调用参数别名处理：比较参数与两个跳转参数实际共用第二个参数，因此转换成特定跳转，不再作为通用 `branch_event`。原始数据中跳到本条最后一个零参数的情况，被明确转换为一次 `refresh` 再继续，不能把该例外推广成允许任意跳入参数区。依据为 OpenLegend `research/evidence/functions/Z_DAT/0x300D9.md` 及 `scene.cpp` 的调用处。

26 号会计算后续脚本 ID，中央库因此直接登记全部 KDEF 程序及不可用原因，不再使用有限场景依赖 profile。运行时根据新的编号查找全局程序，目标不可用时明确拒绝；编号和引用校验仍保留。全量导入消除了按场景收集依赖的限制，但不使未实现指令自动变得可运行。

依据为只读 OpenLegend 的 `src/scene/scene.cpp` 中 `run_event`、`interact`、`use_item` 及角色/队伍辅助函数，`include/openlegend/model/game_snapshot.hpp` 的人物、地图和事件字段定义，以及 `include/openlegend/scene/scene.hpp` 的商店事件常量。标准变量、通用选择、调用、等待和跳转是重制的内容接口扩展，不伪装为原版 opcode。

“导入器接受编号”“程序能通过引用与能力校验”“真实场景剧情已运行验收”是三件不同的事。包含可达未支持指令的原版脚本仍整段记录为不可用，不会跳过未知指令后继续发奖励。世界数据保留全部 100 张地图/事件，其中只有 84 条原始场景元数据，另外 16 个槽位标记 `has_legacy_metadata=false`。库内可重新选择有图像 bank 的预览，远景状态也可修改；游戏内旅行能力另见 [世界移动与场景切换](world-travel.md)，不据此宣称所有玩法已实现。扩展 50 方言明确拒绝；这里兼容 DOS 原版 50 的五物品判断。

## 可运行样例

`content/examples/event-demo.json` 是独立编写的任务数据。以下命令加载中央库并在内存中应用剧情叠加，不复制资源、不生成新场景包，也不修改基础库：

```powershell
.\run.ps1 -EventDemo
.\run.ps1 -EventDemo -Smoke -Report .local/verification/events.json -Capture .local/verification/events.png
```

默认仍跳过开场，主角面前就是测试娃娃。按 E 接任务，打开行囊选“测试信物”并使用，领取一次 100 银两奖励；拒绝、取消、错误物品、重复交谈均有对应分支。截图参数还会输出 `-dialogue.png` 选择面板和 `-inventory.png` 行囊画面。

也可用 `run.ps1 -StoryOverlay 'content\mods\example.json'` 指定自编剧情。叠加的场景编号必须与当前视图一致；程序、对白、物品、变量和不可用程序的 ID 与基础定义冲突时拒绝。当前只支持显式单个叠加，没有多 MOD 自动发现、加载排序或通用替换补丁机制。重启当前场景会保留这份叠加，但任务进度和其他运行状态重新初始化。
