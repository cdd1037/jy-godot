# 战斗架构与原版兼容边界

当前战斗是同一 `GameSession` 内的纯 C# 战棋模块，已接入事件挂起、出战选择、移动、已学武功、用毒、解毒、医疗、药品、暗器、有限敌方行动、胜败、结算和剧情恢复。它还不是完整原版战斗复刻；数据导入、规则测试、宿主交互和 DOS 动态差分是不同层次的验证。

## 状态与职责

| 层 | 类型 | 职责 |
|---|---|---|
| 不可变定义 | `BattleDefinition`、`BattlefieldDefinition`、`MagicDefinition`、`ItemDefinition`、`ProgressionDefinition` | 保存原始字与解析后的基础规则 |
| 共享目录 | `BattleCatalog` | 按 ID 引用战斗、战场、武功、物品与成长规则 |
| 本次战斗 | `BattleSession`、`BattleCombatant` | 出战、站位、占用、回合、行动与胜败 |
| 规则 | `BattlePathing`、`BattleMagicRules`、`BattleAttackRules` | 路径、目标范围、攻击区域、HP/MP 数值与动作提交 |
| 支持与物品 | `BattleSupportRules`、`ItemUseRules`、`IBattleInventory` | 医疗/毒的原版数值，共用药效和权威背包引用 |
| 战后 | `BattleSettlement` | 恢复下限、经验、升级、练功和制作 |
| Godot | `SceneView.Battle`、`AppRoot.Battle` | 绘制、鼠标选格、侧栏按钮与敌方行动节奏 |

友方参战者直接持有会话中的 `PartyState.Roles`，不会另建一份脱离探索状态的人物。敌方从不可变人物定义建立独立运行时副本，不污染全局敌人基线。最多六名友方、二十名敌方；原战斗记录的指定出战、强制出战和各自站位分开解释。战斗选择尚未完成时不提前判胜败。

`Game.Core` 不引用 Godot。出入战斗只替换同一资源库的内存视图，继续使用原 `GameSession`、背包、队伍、地图事件和 `EventRunner`，不会导出战斗包或重建游戏会话。

## 事件 6 与结果恢复

原版 6 号在导入时转换为标准 `battle` 命令，参数为：

```text
[战斗 ID, 获胜目标命令 ID, 落败目标命令 ID, 原始 getExp 标志]
```

目标使用标准命令 ID，不是原版相对字偏移。执行器先检查战斗/队伍/成长资料，再建立 `PendingBattle` 并暂停本次事件；普通确认键不能跳过战斗，也不能替玩家选择胜利。

胜败由参战状态计算。玩家确认返回场景时，`GameSession.FinishBattle()` 先结算一次，再执行原流程最后一次轮末状态，保留结果并消费对应的挂起令牌；随后 `EventRunner.ResumeBattle(token)` 查询会话实际结果，进入胜利或落败分支。旧令牌和重复确认不能重复发经验或再次选择分支。双方都没有存活者时保留原流程“最后判为胜利”的结果次序。

旧资源库缺少战斗资料或成长规则时明确拒绝启动对应事件，需要重新导入完整资源库；不会静默跳过战斗后继续发奖励。

## 原始数据与中心库

本机原版数据包含：

| 来源 | 数量/尺寸 | 解释 |
|---|---|---|
| `WAR.STA` | 140 条，每条 186 字节 / 93 字 | ID 使用记录索引；字 6 为战场，7 为经验，8 为音乐；9–32 保留出战与站位，33–92 保留敌方及站位 |
| `WARFLD.IDX/GRP` | 26 个战场 | 每个战场前 16384 字节为两层 64×64 有符号小端字：地面、建筑 |
| RANGER 第 4 分区（从 0 计数） | 93 条武功，每条 136 字节 / 68 字 | 名称、音效、类型、效果、耗内、十级威力/距离等；未知字原样保存 |
| RANGER 第 2 分区 | 200 条物品，每条 190 字节 / 95 字 | 装备加成、关联武功、药物/暗器数据、需求与制作配方；不能只用物品名称代替 |

WARFLD 不能按固定 16384 字节步长切原档。真实记录中，ID `4,5,6,8,9,10,11,12,14,15,16,17,18` 共十三条为 24576 字节，其余十三条为 16384 字节。导入器按 IDX 逐条定位，只解析前两层；额外 8192 字节不猜作已实现的战斗层。原始 WARFLD 文件完整保存在 source vault，尾数据不会丢失。

中心库将定义存入 `data/battles.json`，将规范化的两层战场连续存入 `data/battlefields.bin`。`LibraryBattleDocument.BattlefieldIds` 给出二进制中的战场顺序，manifest 记录这两个文件及其哈希。所有原始记录在模型中防御复制，战斗修改的是人物运行状态。

真实战斗 0 为“鬥胡斐”：战场 0、总经验 150、音乐 5，主角起点 `(32,20)`，首敌为人物 1 胡斐，起点 `(21,23)`。这些数据提供可运行参照，不代表其音乐、全套动作和全部战斗行为均已还原。

### 图像编号

全部战斗图像和场景、头像、世界图像共用全局去重资产与 `assets/sprites/atlas-*`。bank 是本地编号映射，不复制另一份图集。

| Bank | 原始来源 | 本地 ID | 空记录与索引 |
|---|---|---|---|
| `battlefield/NNN` | `WDXnnn/WMPnnn` | `2 * 帧索引` | 尾 0 sentinel，末帧延伸至 EOF；空帧不采用 SDX 向后别名 |
| `effect` | `EFT.IDX/GRP` | `13000 + 2 * 帧索引` | 普通累计索引，不向后别名 |
| `fight/NNN` | `FIGHTnnn.IDX/GRP` | `16000 + 2 * 帧索引` | 普通累计索引；NNN 为人物头像 ID |

WDX 同时提供战场地面、建筑和静态人物图。静态人物帧为 `5106 + 8 * HeadId + 2 * Facing`。`FMAP.IDX/GRP` 保存在原始资源仓库；参考引擎的生产战斗绘制使用 WDX/WMP，没有据此把 FMAP 当作另一个已接入的战斗图像运行时。

效果与出招帧已经聚合，当前显示仍以静态参战者和范围提示为主；存在 bank 不等于已经播放逐帧招式、EFT 效果或相应声音。透明度由 RLE 覆盖平面决定，色号 0 不一律透明。

### 成长规则

`LegacyProgressionImporter` 只从 `Z.DAT` 提取原始数据：文件偏移 `0x4DF8E` 的三十级无符号经验阈值、原 HP/MP 上限、资质需求和训练奖励参数。读取前检查对应机器指令布局、目标地址及重复常量一致，防止把其他二进制相同偏移当作有效规则。

原始末级阈值为 52000，HP/MP 上限均为 999；资质系数为 `7 - IQ/15`，无关联武功的初始需求倍数为 2，训练奖励为 8/10。中心库只保存这些解析结果，不缓存或执行 DOS 程序；`Z.DAT` 的源哈希可用于追溯。

## 行动规则与有限 AI

目前可进行出战选择、寻路移动、已学武功攻击、用毒、解毒、医疗、服药、投掷暗器、休息和等待。移动考虑建筑、占用与原地形区间，目标选择使用独立的可达判定；路径实现使用有界 64×64 BFS，没有复制 DOS 队列溢出或越界别名。移动后可以继续行动。

武功按原十级熟练度计算选择距离、攻击距离、区域和双击次数。HP 与 MP 攻击使用不同数值核，读取真实武功、装备加成、武学常识及特定兵器配合；没有添加脱离已学武功的虚构“普通攻击”。熟练度、内力消耗、体力尾部与个人经验在统一战斗动作中提交。事件、攻击、休息和结算消费同一个执行器随机序列。

敌方当前采用有限策略：按距离寻找存活对手，尝试可用武功，必要时寻路靠近，再攻击或休息。它调用与玩家相同的合法动作；未实现原版完整的强弱目标、专长、医疗、用毒、道具等策略组合。代码中的 AI 策略说明与此限制一致。

### 医疗、毒与战斗物品

`BattleSession.Support` 调用纯 `BattleSupportRules`，不借用后续 NG+ 公式。用毒的菜单门为体力严格大于 10 且能力至少 20，解毒/医疗为体力严格大于 50 且能力至少 20；射程按各自技能 `/15+1`，不采用参考工程现版本的技能 100 封顶。几何范围使用同一目标路径图。

- 用毒按原差值/4及毒值容量夹限，不额外把溢出毒转换成生命伤害。
- 解毒始终先取两次 `bounded(10)`，保留失败门、当前毒值上限和严格 100 边界。
- 医疗按伤势四档缩减技能，再取一次 `bounded(5)`，保留伤势过重失败和满血截断；命中友方时医核及共同尾部各扣 2 体力，总 4。
- 合法范围内对空格或错误阵营确认支持行动，仍走共同尾部扣 2 体力并加一次个人经验，但不调用疗效/毒核或消费其随机数。越界、超距与菜单准入失败不消耗行动。

友方战斗物品通过 `IBattleInventory` 直接使用同一 `GameSession` 背包；归零同时清对应物品 ID，未复制临时战斗背包。敌方规则只操作敌人自身四个携物槽及数量，耗尽时按原槽位压缩，不借用玩家库存。当前 `StepEnemy` 还不会自动选择新增支持/物品动作；相关规则测试中的敌方调用不等于完整 AI 已接入。

type 3 药品复用[探索中的 `ItemUseRules`](items.md)，使用唯一执行器的 RNG。玩家零显示效果时保留物品但结束行动；敌方药品规则仍按原携物消费。暗器 type 4 使用独立原公式：伤势四档、随机基数的 signed-word 回绕、玩家与敌方不同的加毒分支；玩家非正物品毒性仍消费原两次随机。暗器空格或友方目标直接返回，保留行动与库存；成功不另扣体力或发武功攻击经验。异常负伤势、负最大生命及越界目标按已列明的平台安全边界拒绝。

所有数值先计算再提交，药品与暗器成功消耗一次。自定义库存适配器必须保持 `TryConsume` 原子性；外部随机回调已经消费的状态无法自动回滚。本批按同步动作提交数值，未播放原 EFT、伤害闪烁或其延迟，不能把数值回归称为逐帧动态验收。

普通轮末应用伤势/中毒状态。伤势大于 0 可以绕过中毒分支的存活、体力、隐藏门；严格负值才补为 1，恰为 0 不当作负值。战斗结果确定后，结算返回前仍执行一次同样的原版公共尾部；该调用只执行一次，已确定的胜败不会因结算恢复或最终状态变化重新裁定。

## 战后结算与原版数值

HP 耗内系数保留为会话内跨战状态：HP 命中更新，纯 MP 命中和空击沿用旧值。正常 DOS 启动清零区覆盖原全局 `word_E6EC2`，因此初值采用 0；依据为 `research/ida/reports/Z_DAT.targets.txt:10435` 附近的启动清零链。这是静态机器证据，不是动态内存 oracle。下一战继续使用上一战的系数；独立新会话重新初始化。

当前 OpenLegend 的生产 C++ 部分已经加入 NG+ 数值扩展，因此结算依据是它保存的原机器证据合同，不直接照搬扩展后的大数、周目倍率或三十级以上成长。

- 敌方恢复 HP/MP、体力并清伤势/中毒。友方按最大生命的五分之一补生命下限；死亡者体力至少恢复至 10。
- 胜利时把战斗总经验按战斗结束时仍存活的友方人数均分，只加入这些友方的个人奖励。已有动作/伤害经验继续保留。
- 每个参战槽的经验都入账，再决定是否显示经验或进行后续成长。原版经验字段先保留低 16 位，再按无符号值限制到 60000；不能改成无限精度累计。
- `getExp` 严格等于 1，或实际获胜时，才对友方启用消息、升级、练功与制作入口。标志 9 不等于 1；落败且标志 0 也不会抹去已经获得的个人动作经验。
- 升级最多到 30，保留原资质分档、随机调用顺序、生命/内力成长、字回绕及原上限。没有 NG+ 阈值外推。
- 练功需求使用首个同武功槽；成功时更新所有符合条件的重复槽，保留满级阻止学习、首空槽只写武功 ID 等原行为。制作先对五配方拒绝采样，再按是否已有产物决定数量随机调用。

角色按 `RoleState` 引用去重建立候选副本，再提交回权威角色；不会改敌方定义。结算结果存于 `LastBattleSettlement`，可用于概要显示。

两项明确的呈现/存储适配：背包仍是“正数量字典 + 物品 ID 集合”，未复原 DOS 的重复物品槽、负数量或空槽旧计数；制作遵循这一现有背包语义。结算结果统一提交后提供消息数据，未复制 DOS 每条经验/升级/练功提示等待确认后才提交的细分时序。随机回调按顺序消费，异常时无法自动回滚外部 RNG。

## 运行与验证

完整库需要重新导入战斗定义、成长数据及共享图像。示例使用原版战斗 0，不复制一套战斗专用资源：

```powershell
.\run.ps1 -BattleDemo
.\run.ps1 -Smoke -BattleDemo -BattleSmoke
.\run.ps1 -Smoke -BattleDemo -ItemActionsSmoke
```

默认测试启动仍跳过开场；面向娃娃按 E，选择开始切磋，再确认出战。侧栏提供移动、武功与攻击、支持行动、物品、休息、等待；目标行动通过点击地图格子完成，医疗/解毒可点击自己。Esc 只取消尚未确认的目标选取。结果确定后点击返回场景，执行对应胜败对白。

战斗冒烟通过按钮和鼠标输入驱动选择及战术行动，读取实际胜败再检查结算、同一场景/会话和剧情恢复。默认原始弱主角可能在攻击前就落败；这条流程不预设必胜。另有明确标识、单独记录的准备夹具调整主角数值，用于覆盖攻击操作和胜利返回，不能把它称为原始数值获胜。具体日志与截图以统一验证记录为准。

物品行动冒烟明确把本次主角最大生命设为 999、防御 1000、医疗/解毒/用毒/暗器技能 120，并补入测试库存；敌人与战场仍读原版战斗 0。通过真实背包按钮及战斗选格走完 9 项检查，最后暗器造成实际胜利并返回同一剧情。它是集成准备夹具，不是原始弱主角的平衡或获胜验收；正常 `-BattleDemo` 不做这些修改。

仍待完成：完整原版 AI 选择器，逐帧移动/出招/伤害与效果播放、战斗音效和音乐，以及 DOS 运行时动态差分。武林大会与结局另未接入；死亡/载入已有[独立生命周期支持](persistence.md)。
