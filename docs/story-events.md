# 对话与剧情事件

## 运行边界

`Game.Importing` 一次导入全部 KDEF/TALK，将可完整转换的原版脚本编译为标准 `EventCommand`，公共程序和对白集中存入 `data/gameplay.json`；`Game.Content` 负责加载，`Game.Core.Events.EventRunner` 运行这些命令。Godot 不解析原指令，不直接改写人物、背包和事件状态。

`GameLibrary.OpenScene` 创建共享资源的内存场景视图，`GameSession` 创建队伍和世界的运行时副本。事件改写存入会话，界面从只读视图获得图片、位置和待显示内容。预览另一场景会新建会话，不生成第二份资源库。

确认页面使用单调递增令牌。旧令牌、重复点击和同一帧的按钮/键盘双重确认不推进新页。按住确认键不会自动连跳。行走在整个事件运行期间被核心拒绝，包括动画间隙。

事件执行基础现包含 61 种命令。本轮新增 `exit_music`、`music`、`statue_animation`、`tournament_trials`、`ending`、`shop`，源码覆盖原版 68 项编号映射，但没有重跑编译审计。历史 998 段接受、20 段拒绝不代表本轮结果；也不代表完整原版剧情运行验收。战斗结果来自同会话的实际参战状态，详见 [战斗](battles.md)；完整接口见 [事件编写说明](event-authoring.md)。以下开场合同和命令表描述原版主角家的既有接入。

## 原版开场合同

测试启动默认不显示开场。`GameSession` 的 `skipOpening` 选项通过同一个事件执行器快速完成初始程序，保留实际地图、人物和背包变化，清掉启动声音；Godot 在构建会话完成后才显示场景，因此不会弹出开场对话。显式使用 `run.ps1 -PlayOpening` 时正常播放。此选项只用于测试入口，不改写内容包或原版资源，后续人物和箱子交互正常显示对话。

- 场景 70，位置 `(19,20)`，朝向 right，初始人物图片 6890。
- 脚本 691，共 66 条命令，27 段对白，导入后按三行一页生成 52 页。
- 主角动画：6890–6932、6934–6986、6988–7000 两次，步进 2。
- 娃娃动画：6820–6860、6862–6888，步进 2；播放 `E24.WAV`。
- 结尾关闭事件 0 的自动脚本，事件 1 保留交互脚本 692；人物朝向 up，回到普通行走图片。
- 事件 1 后续交谈按原 LCG 在 2547–2564 的 18 段台词中选择。当前会话种子默认为 1；不声称重现原 DOS 新游戏之前的完整 RNG 消费流。
- 箱子脚本 693–700：更换图片、关闭事件、显示一次性奖励。
- 床脚本 931：休息选择；否分支直接结束，是分支依次显示 2843、刷新、淡出、队伍休息、朝向 down、刷新、淡入、2844、刷新并结束。伤势低于 33 且未中毒的成员恢复生命、内力和体力。13/14 暂用约 450ms 的近似渐变。

动画每帧采用两个 BIOS tick 的名义时长 `2*65536/1193182` 秒；刷新命令让出至下一次宿主推进。此阶段保留逻辑顺序，不声称整个 Godot 帧循环逐时钟等同 DOS。

## 剧情演出

25 号镜头平移按 KDEF 的起点/终点计数，X 轴完成后才处理 Y。每轴包含起点、不包含终点，每帧等待两个名义 tick；只改镜头，不改玩家。镜头偏移保留到后续成功移动、传送或切图时清理，不是永久平滑跟随。

30 号剧情行走的 source 参数只决定循环次数，不把玩家传送到 source；从实际位置逐格尝试，X 后 Y，保留碰撞，阻挡仍消费动画帧。每步等待三个名义 tick，结束清除步行动画偏移并额外刷新站立帧。不增加手动行走统计，也不在每格调用自动剧情或出口检查；事件控制权始终留在同一个 Runner。

44 号双动画按第一组区间推进，同帧先写第一目标、再写第二目标；第二个结束参数在原机未读，导入时丢弃。事件 -1 表示玩家，同目标由第二次写入覆盖。图片值每帧加 2，写入时保留低 16 位，每帧等待两个名义 tick，末帧完成等待后才继续剧情。

以上三类演出使用现有执行器的定时续行。镜头和行走最多 4096 步，双动画最多 4096 帧，这是重制防止异常内容长时间阻塞的限制。`ScenePresentationTests` 的合成用例覆盖坐标顺序、边界、碰撞、等待、覆盖和回绕；真实剧情完整运行验收另行记录。新增转换后需重新导入中央库，既有库不会自动补回先前拒绝的脚本。

57 的石像演出先播放六张主角图，再同步更新事件 2/3/4 的 29 帧，主角到 7688 后保留最后图像。58 的武林大会是同一 Runner 内的有限续行，五组各随机选三个不重复对手，调用真实战斗与结算，败北转入死亡菜单；不会由宿主选择胜败。62 先隐藏主角、完成双事件动画，再终端移交结局。结局显示保留 443 帧滚字、221 帧动画、3244 帧名单和两次确认，时长近似，完成后不返回旧剧情。

64 先显示招呼 2974，再发布 `PendingShop`。宿主商店只选一项、买一件或取消；成功 2976、钱不足 2975 都由原 Runner 显示并在确认后收店，设置原指定辅助事件的自动脚本 939。商店库存来自 RANGER 第 5 项，运行变化与会话一起保存，不提供出售或批量购买。

8 保存一次离场音乐覆盖，离场消费后清除；66 请求立即播放且同曲也重启。曲目状态归 Core，GAME*.XMI 只由 Importing 离线转换为 120Hz 短消息乐谱。Windows WinMM 系统 GM 后端负责实际发声；它不还原 DOS FM 音色。商店、音乐与结局均由独立宿主组件连接，不扩展第二套脚本运行时。

## 开场使用的标准命令

| 命令 | 参数 | 原版来源 |
|---|---|---|
| `refresh` | 无 | 0 |
| `dialogue` | 对话 ID、头像 ID、样式 | 1 |
| `add_item` | 物品 ID、数量 | 2 |
| `change_event` | 场景、事件及 11 个字段，-2 保留 | 3 |
| `animate` | 事件索引（-1 为主角）、开始图片、结束图片 | 27 |

每条命令保留原始字偏移作为 ID，并记录来源 opcode，错误报告包含程序和命令位置。未知或尚未支持的原版指令导致整段事件不可用，记录在 `unavailable_programs`，不静默跳过。床的休息事件 931 已接通。

## 格式 3 中央资源库

新导入使用一套中央资源，而不是让主角家携带其他场景也要用的独立副本：

- `data/gameplay.json`：全局程序、分页对白、物品名称、初始背包、队伍、商店初始定义和不可用事件原因。
- `data/scene-index.json`、`data/world.layers.bin`、`data/world.events.bin`：统一场景索引、地图与事件。
- `data/sprites.json`、`assets/sprites/`：头像和场景图像的原始 bank/编号映射及内容去重图集。
- `data/audio.json`、`data/source-index.json`、`assets/source/`：音频定位及来源资源缓存；WAV 保留 `.wav` 后缀。
- 规范化音乐乐谱由 `data/audio.json` 的 `scores` 定位；结局字图/动画为 `data/ending.json` 与 `data/ending.pixels.bin`，运行时不调用原始归档解码器。

主角家的图片和剧情从公共定义中获取，初始人物、队伍和背包按 RANGER 读取。原版世界保留 100 张地图与 84 条原始场景元数据；没有图像 bank 的记录不能作为可行走预览打开。旧格式 1/2 场景包只保留兼容读取。资源实际数量与验证结果见 [验证记录](verification.md)，库布局见 [中央资源库](resource-library.md)。

26 号对事件脚本编号的增量修改可引用全局程序集合，不再通过每个场景的有限依赖 profile 收集资源。目标程序若含未实现指令，仍保留明确不可用原因，触发时不会跳过未知指令。

`-EventDemo` 把独立编写的 `content/examples/event-demo.json` 在内存中叠加到公共定义，不复制图片、对白或资源目录。当前单个叠加要求目标场景一致，并拒绝与基础定义重复的 ID；它不是通用多 MOD 排序器。

## 验证

本轮六项指令、商店/音乐/结局组件均未重新导入资源，也未执行编译审计、构建、测试或画面验收。旧库缺少新的程序集合及规范化资产，必须重新导入到新目录，新增脚本才能实际进入。以下描述既有测试职责与历史冒烟入口，不是本轮通过记录。

`EventTests` 验证分页、确认令牌、动画等待、状态副本、自动事件到达时机、音效队列、随机台词及箱子防重复。

`OriginalStoryTests` 直接导入用户提供的真实资源，跑完 691，检查所有对白、最终图片和触发器；再寻路交谈娃娃、打开全部 8 个箱子，核对奖励与禁止重复领取，并执行床的拒绝/休息分支，检查黑场期间的恢复顺序。

Godot 冒烟通过输入动作确认全部 52 页、等待动画结束，再走 6 格并验证一次障碍，检查 691 只完成一次、事件 0 被关闭和音效 24 仅入队一次。真实窗口截图另行检查分页、头像及布局，不将无界面绘制调用替代画面验证。

完整开场冒烟使用 `-PlayOpening`；普通启动现先显示标题，选择新游戏后仍按测试阶段设置跳过开场。`-DirectPlay` 与冒烟入口直接进入场景。`-EventDemo -Smoke` 的既有覆盖包括任务选择、行囊物品使用、等待与调用、任务状态和一次性奖励；行囊迁移后的驱动尚未重跑。
