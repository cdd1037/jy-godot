# 原版指令兼容与审计

原版解释器有 `0..67` 共 68 个操作码，另有 `-1` 结束标记。“扩展 50”是修改版引擎赋予 50 号指令的新方言，不是原版指令总数。原版 50 固定占 8 个 word，含五个物品 ID 和两个分支偏移。

本项目用统一的 C# 事件命令执行剧情。原版编号是导入格式，标准命令数量不等于兼容的原版编号数量。

当前有 62 个编号的转换实现、55 种标准命令，另支持 `-1` 结束。6 已接入战斗及胜败恢复，15/24 已接入死亡/载入菜单生命周期，25/30/44 已接入镜头、剧情行走和双动画；未接入的 6 项是 `8,57,58,62,64,66`：离场音乐、特殊演出、武林大会、结局、商店与音乐播放。

接入 15/24 后，实际 C# `audit-events` 对已知原版 1,018 条记录得到 **998 段完整编译通过、20 段拒绝**，比上一轮 910/108 净增加 88 段。当前首个阻塞为离场音乐 8（15 段），57/58/62/64/66 各 1 段。上一轮被 15 阻塞的 94 段中，有 6 段在其他可达分支进一步遇到 8；同一脚本可能有多个阻塞，这些数量不是全部指令出现次数。

实际编译报告为 `.local/verification/lifecycle-opcode-audit.json`，已确认原版 IDX/GRP 身份，空记录为 0，`execution_verified=false`。它不执行完整剧情，不能视作运行验收；战斗动作和 AI 的剩余范围见 [战斗说明](battles.md)，最新验证见 [验证记录](verification.md)。已经生成的旧库仍保留导入时的程序集合，需要重导入才能增加先前不可用的脚本。

中央库全量导入 KDEF，并保存每段可编译程序或拒绝原因。26 号的动态脚本编号因此不再受有限场景依赖 profile 限制；运行时仍检查编号、内容引用和需要的角色/世界能力。全局登记程序不代表其所有条件分支都已实际执行，也不代表尚未支持的编号可以运行。

## 审计口径

`LegacyEventAudit.Read(sourceDirectory)` 只读取 `KDEF.IDX/GRP`，枚举所有非空记录并逐段调用真实的 `LegacyEventCompiler.Compile`。编译器必须完成整个可达控制流和标准命令校验；遇到未实现操作、截断或非法分支，整段记录被拒绝，不把已解码前缀计为支持。

工具入口（输出要求新文件且位于原版资源目录之外）：

```powershell
dotnet tools/Game.Tools/bin/Debug/net10.0/Game.Tools.dll audit-events --source '原版目录' --output '.local/opcodes.json'
```

报告结构包括：

- `archive_entry_count`、`empty_entry_count`、`compiler_accepted_count`、`rejected_count`。
- `source_hashes`：两个输入文件的 SHA-256，和 `known_original_archive` 身份标识。
- `scripts`：每段编号、字节数、是否完整编译通过、命令数、来源操作码、标准命令种类和拒绝原因。
- `execution_verified=false`：这份报告不执行剧情，也不验证角色、对话、贴图、场景引用及宿主战斗、菜单等能力。完整编译通过不能直接写成“原版游戏可完整运行”。

拒绝记录的命令与操作码数组为空，表示没有可执行的完整编译结果，不表示原始记录不含这些操作码。报告只保存结构和诊断，不复制原版对话、指令参数或资源内容。

对应原版共 1,018 条非空记录。测试中的合成 KDEF 专门覆盖逐记录拒绝、继续审计、哈希、只读、序列化和方言拒绝；它们不属于原版资产。`OriginalAssets` 测试另读取真实资源验证身份和记录计数。机器证据来自 OpenLegend 的静态反汇编与独立资源 oracle；这里没有进行 DOS 运行时逐帧差分。

### 死亡与载入的生命周期

15 和 24 归一化为终端命令，编译器不把菜单之后不可返回的顺序字节当作可达剧情。运行时通过唯一事件解释器的 `PendingLifecycle` 挂起，保持行走与交互锁定；没有“关闭死亡提示后继续”或“假读档成功”的接口。

宿主先读取存档、验证资源库和剧情身份、恢复独立候选会话，再准备全部视图资源；只有准备成功才提交替换并永久废弃旧 VM 及调用栈。失败保留原会话与菜单请求；成功后的新会话不会重播开场或恢复旧命令后继。存档保存的是稳定自由行动状态，不序列化活动事件、战斗或生命周期 continuation。

原版 15 在当前 palette 上加载 `DEAD.BIG`，绘姓名、日期、固定文字和菜单；24 从黑底进入独立菜单，并有多层旧场景退出和载入淡变。Godot 菜单布局、画面与过渡采用重制近似，不能以编译通过宣称这些像素与时序已对齐。真实脚本没有首条即为 15 的记录，最短前缀仍包含对白与战斗；24 在原版 KDEF 中完全未用，因此直接进入这两类菜单的 UI smoke 使用合成夹具，不冒充真实原版败北流程。

### 55 号的操作数别名

原版全部 28 处 55 号的后三参数都是 `-1,14,0`。机器因此跳到该指令的第五个 word，即 argument4 所在的 `0`。它被解释为 opcode0，额外呈现场景一次，再继续 `oldPC+5` 的后续程序。

编译器仅对这个经过证据确认的别名入口显式建模：55 归一化为固定跳转，`oldPC+4` 的 `0` 归一化为一次 Refresh。这个例外不能扩展为“所有跳转都允许落入任意操作数”；普通分支仍验证目标是合法指令入口，越界与不受支持的重叠布局拒绝整段脚本。

### 扩展 50 的方言边界

扩展 50 与原版没有可靠的通用字节魔数。某一小段扩展字节恰好满足原版的 8-word 格式，并不能证明其含义相同。调用者必须从内容包清单或导入配置指定方言，不能猜测；审计 API 的默认 `DosOriginal` 明确表示调用者选择原版解释。

当前 `LegacyScriptDialect.Extended50` 会在读取与编译前明确拒绝。原版哈希不匹配仅表示来源未经该身份确认，不自动把内容认定为扩展版，也不自动保证兼容。后续迁移旧 MOD 应建立独立的格式转换器，输出同一套标准命令；不应把扩展 50 偷偷解释为五物品判断，更不应实现 DOS 内存写入。
